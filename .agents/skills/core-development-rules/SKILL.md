# 에이전트 행동 경계 표준 (Always / Ask First / Never - 사장님 절대 헌법)

본 문서는 사장님의 절대 지침으로, HDDGOD 프로젝트의 모든 코드 작성, 리팩토링, 버그 수정, 빌드 및 배포 작업 시 **무조건 최우선으로 준수**해야 합니다.

---

## 🟢 Always (항상 준수할 것)
1. **성공 기준을 먼저 정하고 실행하라**:
   - 코드를 작성하기 전, "어떤 상태가 되어야 성공인가?"라는 명확한 검증 체크리스트를 먼저 정의한다.
   - 단순 에러 부재가 아니라 실제 PC 동작, 패킷 송수신 수치, 화면 표출 여부 등 객관적인 데이터로 성공 여부를 입증한다.
2. **시킨 것만 견고하게 코딩하라 (축소 금지)**:
   - 요청받은 작업 범위만을 정밀하게 구현한다.
   - 200줄짜리 견고한 코드가 50줄로 날림 축소되지 않도록 기존의 예외 처리, 동기화 락, 로깅, 안전장치를 철저히 보존한다.
3. **안 되면 즉시 멈추고 조언을 구하라 (삽질 방지)**:
   - 오류가 반복되거나 예상대로 작동하지 않을 때 혼자서 무리하게 땜질(삽질)을 반복하지 않는다.
   - 즉시 멈추고 시도한 내용, 발생한 에러, 원인 분석을 사장님께 솔직하게 보고하고 필요한 조언과 정보를 요청한다.
4. **에이전트 추가를 적극 제시하라**:
   - 복잡한 대규모 분석, 심층 리서치 또는 병렬 검증이 필요한 경우 혼자 시간을 끌지 않는다.
   - 전문 서브에이전트(리서처, 테스터, 리뷰어 등) 추가 협업을 사장님께 적극 제안하여 업무 효율을 극대화한다.
5. **실제 화면 캡처 교차 검증 의무화**:
   - GUI 프로세스 기동이나 화면 제어 시 PID나 HWND의 단순 존재만으로 성공을 단정 짓지 않는다.
   - 반드시 `mss`로 실제 모니터 화면을 캡처하여 시각적으로 온전히 표출되었는지 직접 교차 검증한다.

---

## 🟡 Ask First (반드시 먼저 물어볼 것)
1. **짐작하지 말고 애매한 부분은 질문하라**:
   - 사용자의 요구사항에 모호한 점이나 복수의 해결 경로가 있을 때 자의적으로 판단하거나 추측 코딩을 하지 않는다.
   - 확실하지 않거나 부작용이 예상되는 부분은 즉시 사장님께 질문하여 의도를 명확히 확인한 후 진행한다.
2. **구조적 변경 및 주요 파일 삭제**:
   - 대규모 아키텍처 변경, 새로운 외부 라이브러리/패키지 추가, 기존 파일 삭제가 필요할 때는 사장님의 사전 승인을 얻는다.

---

## 🔴 Never (절대 하지 말 것)
1. **짐작 코딩 절대 금지**:
   - "이렇게 하면 되겠지"라는 추측 기반 코딩을 일체 하지 않는다.
2. **시키지 않은 코드 건들기 절대 금지**:
   - 요청받지 않은 정상 모듈, 파일, 설정값, UI 요소를 임의로 수정하거나 "개선"하려 들지 않는다.
   - 변경이 필요한 최소 단위의 코드만 수정하여 부작용을 원천 차단한다.
3. **손님 이용 중 좌석 간섭 절대 금지**:
   - 피카 카운터상 손님이 이용 중(`USING`)인 좌석(예: PC-01 등)은 원격 재부팅, 에이전트 강제 업데이트, 화면 제어 등 어떠한 조작도 절대 수행하지 않는다.
4. **기본 Git 동기화에 구글 드라이브 사용 금지**:
   - 모든 버전 관리는 작업 PC 로컬(`C:\HDDGOD`)과 GitHub 원격 저장소(`origin`) 간에 직접 동기화한다.
   - **단, 필요시나 사장님 요청 시 구글 드라이브(`G:\내 드라이브`, `G:\` 등)에 접속하여 참고 자료나 백업 데이터를 가져오는 것은 완전 허용된다.**
5. **백그라운드 가상 세션 기동 및 마우스 좌표 의존 금지**:
   - GUI 프로그램 기동 시 일반 `Popen` 단독 기동을 금지하고 반드시 `si.lpDesktop = r"WinSta0\Default"`를 명시한다.
   - 해상도나 DPI에 취약한 마우스 좌표 클릭(`pyautogui`) 대신 Win32 컨트롤 메시지 주입을 최우선한다.
