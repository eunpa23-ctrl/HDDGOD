# ⚡ 제우스 HDD PROTECTOR - 검증 완료 핵심 기능 및 운영 가이드

본 문서는 제우스 시스템에서 실제 매장 테스트 및 운영을 통해 검증 완료된 핵심 기능과 아키텍처 규칙을 정의합니다.

---

## 1. 🖥️ 듀얼 관리 서버 시스템 (카운터 100 + 메인 서버)

### 1.1 카운터 관리 서버 (HOST 100 / `192.168.0.100`)
- **역할**: FastAPI 기반 중앙 관제 허브, WebSocket 중계, 피카 카운터 화면 직접 제어
- **자원 모니터링**: 카운터 PC 자체 CPU, RAM 점유율 및 제우스 프로세스 메모리 실시간 측정
- **메모리 최적화**: 
  - 엔드포인트: `POST /api/optimize_memory`
  - Windows `EmptyWorkingSet` API를 통해 전체 프로세스의 유휴 캐시 메모리 원클릭 회수
  - 자동 메모리 정리 데몬: RAM 80% 이상 30초 지속 시 자동 회수 가동

### 1.2 메인 서버 (SERVER_MAIN / `192.168.0.2`)
- **식별 체계**: 과거 "9번 PC" 표기를 완전히 탈피하고, **`메인 서버 (SERVER_MAIN)`** 전용 카드로 독립 분리
- **전용 에이전트 (`ZeusAgent_Server.exe`)**:
  - `is_server_node() == True`로 판별되어 서버 전용 동작 수행
  - 3초 주기 하트비트로 CPU, RAM 점유율(%) 및 실제 사용 용량(GB)을 실시간 수신
  - 카운터/모바일 관제 화면에서 원격 유휴 메모리 정리(`EmptyWorkingSet`) 원클릭 실행
  - 윈도우 원격 데스크톱(MSTSC RDP) 및 내장 웹 스트리밍 화면 제어 완비

## 2. 🎮 일반 손님 PC (1번~8번) 무부하 초경량 에이전트

### 2.1 손님 PC 무부하 원칙 (Zero-Overhead for Gaming)
- **CPU/RAM 측정 원천 배제**:
  - 대시보드 손님 PC 카드에는 CPU/RAM 정보가 표기되지 않으므로, 손님 PC에서는 3초 주기 `psutil.cpu_percent()` 및 `psutil.virtual_memory()` 측정을 **100% 생략** (`CPU: 0.0`, `RAM: 0.0` 고정).
  - 게임 프레임 드랍 및 불필요한 백그라운드 리소스 낭비를 원천 차단.
- **손님 게임 보호 메모리 락**:
  - 손님이 실제 이용 중(`USING`)인 PC에는 유휴 메모리 정리 명령이 전달되더라도 자동으로 건너뛰어 게임 렉 발생을 방지.

### 2.2 피카(PicaLive) 관리프로그램 3단계 상태 판별
- `LOCKED`: 빈자리 화면보호기 잠김 대기
- `USING`: 손님 실제 이용 중 (후불/선불 로그아웃 감지)
- `ADMIN`: 점주 관리자 로그인 상태 (우측 상단 관리자로그아웃 감지)
- **카운터 연동 우선권**: 카운터 PicaLive 관리 화면의 실측 색상(좌석별 픽셀 분석)을 최우선 판별값으로 적용.

### 2.3 넷플릭스 자동화 & 보안
- Chrome CDP(9222) 포트 연동 및 바탕화면 바로가기 영구 보장
- 4자리 이메일 OTP 필요 시 서버가 네이버 메일을 실시간 파싱하여 자동 주입

## 3. 📦 OTA 무인 업데이트 파일 완전 분리 체계

손님 PC와 메인 서버의 에이전트는 역할과 설정이 상이하므로 **디렉토리, 실행 파일, 버전, 다운로드 API를 완전히 독립 관리**합니다.

| 구분 | 손님 PC (1~8번) 전용 | 메인 서버 (SERVER_MAIN) 전용 |
| :--- | :--- | :--- |
| **배포 경로** | `deploy/ClientDeploy/core/` | `deploy/ServerDeploy/core/` |
| **바이너리** | `ZeusAgent.exe` | `ZeusAgent_Server.exe` |
| **버전 파일** | `version.txt` (`4.2.2`) | `version_server.txt` (`4.2.2-server`) |
| **버전 API** | `/api/version/client` (기본 `/api/version`) | `/api/version/server` |
| **다운로드 API** | `/api/download/update/client` | `/api/download/update/server` |
| **배포 버튼** | 상단 **[손님 PC 전체 업데이트]** | 메인 서버 카드 **[전용 업데이트]** |

### 3.1 상호 오배포 방지 규칙
1. **일괄 명령 시 메인 서버 자동 제외**:
   - `sendCommandAll('UPDATE_AGENT')` 실행 시 메인 서버(`192.168.0.2`, `PC-09`)는 자동으로 대상에서 제외되어, 손님 PC용 파일이 메인 서버를 덮어쓰는 위험을 원천 차단.
2. **에이전트 자체 분기**:
   - 에이전트가 업데이트 실행 시 `self.is_server_node()`를 검사하여 메인 서버이면 `/api/download/update/server`에서 전용 파일을 다운로드.
3. **무인 교체 프로세스 (`update.bat`)**:
   - 다운로드 완료 파일 크기 검증(최소 5MB 이상) 후, 3초 프로세스 종료 $\rightarrow$ 새 파일 덮어쓰기 $\rightarrow$ 재기동 루프 수행.

## 4. 📱 모바일 관제 대시보드 (`/mobile`) 핵심 규칙

### 4.1 로그 자동스크롤 피드백 루프 방지
- 모바일 로그 모달에서 [자동스크롤 ON] 버튼을 누를 때 부드러운 스크롤(`smooth`) 중 `scroll` 이벤트가 발화하여 바로 `OFF`로 꺼지는 버그를 해결:
  - `isProgrammaticScroll = true` 플래그 및 300ms 락 적용
  - 프로그래밍 이동 중에는 scroll 이벤트 무시
  - 사용자가 손가락으로 직접 위로 올릴 때만 `OFF`, 바닥에 오면 `ON` 복귀.

### 4.2 손님 이용 중 원격 접속 확인 팝업
- 피카 상태가 `USING`인 좌석을 모바일에서 [원격] 클릭 시, 즉시 열지 않고 경고 모달을 띄워 점주의 의도된 접속인지 재확인 (손님 프라이버시 및 오작동 방지).
